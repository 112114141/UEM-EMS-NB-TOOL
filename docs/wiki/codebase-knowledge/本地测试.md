# 本地测试

## 概述 <!-- category:overview -->
本模块提供抢课核心引擎的本地端到端测试能力。通过内嵌一个模拟教务系统 HTTP 服务器（MockHandler），在 localhost:18888 上复现教务系统的首页、选课页面、QueryCourse 与 SelectCourse 接口，随后驱动 GrabCore 依次执行时间校准、Cookie 检查、接口探测、课程查找、选课提交、秒抢与捡漏等完整流程，无需连接真实教务系统即可验证核心逻辑正确性。

## 架构设计 <!-- category:architecture_design -->
模块由 MockHandler、run_mock_server、test 三部分组成。MockHandler 继承 BaseHTTPRequestHandler，通过 do_GET/do_POST 路由请求：GET 返回首页与含 queryUrl/selectUrl 的选课页 HTML，POST 按方法名分发 QueryCourse（返回课程列表 JSON）与 SelectCourse（依据全局 course_remaining 余量返回成功或已满）。run_mock_server 在守护线程中启动 HTTPServer。test 函数创建 GrabCore 实例，串行调用 calibrate_time、check_cookie、detect_apis、find_course、submit_select、run、_scavenge，并通过修改全局 course_remaining、select_count 模拟余量变化与提交计数。依赖方向：test_local → grab_core。

## 编码规范 <!-- category:coding_conventions -->
1. 测试流程以编号步骤分段（`=== 1. 时间校准 ===`），每步打印 OK/FAIL 结果便于人工核对。
2. 模拟状态使用模块级全局变量（course_remaining、select_count），在 test 内通过 global 声明修改。
3. Mock 请求路由以字符串包含判断（`'/xsxk/' in self.path`、`'QueryCourse' in self.path`）实现，匹配教务系统真实路径片段。
4. 日志输出统一通过 log_func 闭包注入 GrabCore，测试侧用 print 承接。
